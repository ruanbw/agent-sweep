## 1. 产品目标、用户与信任模型

### 1.1 一句话

**AgentSweep 让 macOS 用户在一屏内看清本机所有 AI Agent 的会话占用，并在可核对、可撤销的前提下清理它们。**

### 1.2 目标用户

| 优先级 | 用户 | 场景 | 他们最怕什么 |
|---|---|---|---|
| 主要 | 同时使用 3 款以上 AI 编码 Agent 的开发者 | Claude Code、Codex、Cursor、Zed 各留了几十上百条会话，`~/Library` 悄悄涨到几个 GB | 删错正在用的会话；删完发现空间没释放 |
| 次要 | 磁盘吃紧的 Mac 用户 | 不知道哪些目录能删，不敢碰 `~/.claude`、`~/.codex` | 永久删除；看不懂技术路径 |
| 增量 | 新 Agent 尝鲜者 | 装了目录里没有的 Agent，AgentSweep 看不到它 | 收录后找不到会话；适配器写坏 |

共同点：他们不是来「管理文件」的，是来**做一次有把握的清理**。界面不承担会话全文阅读器的角色。

### 1.3 核心任务（按发生频率排序）

1. **找到占用**：按 Agent、关键词、体积、时间缩小范围，确认哪几条值得清理。
2. **安全清理**：知道每条会话会去哪、会不会释放空间，然后一次确认。
3. **找回误删**：清理后 24 小时内，从三个入口中的任意一个撤回。
4. **纳入新 Agent**：把「发现」里的候选目录收录成 Agent，让下一轮扫描覆盖它。
5. **日常巡检**：扫一眼扫描结果与失败项，确认没有异常增长。

### 1.4 信任模型

> **AgentSweep 只做你确认过的事：显示真实数字、说清文件去向、留好撤销，任何删除都能在发生前核对、发生后撤回。**

拆成六条可验收的承诺：

| # | 承诺 | 用户可见证据 |
|---|---|---|
| T1 | 扫描只读，确认前不写盘 | 首次打开与扫描期间没有任何「已修改」提示；扫描按钮文案始终是「扫描」 |
| T2 | 数字诚实 | 废纸篓模式空间账本写「真实释放 0 B」；清理回执不把废纸篓说成释放 |
| T3 | 默认可逆 | 默认「移入废纸篓」；批次回执可撤销；索引先备份再改 |
| T4 | 不替用户选 | 点击行只移动焦点；`⌘A` 只选可见项；被筛掉的已选会话必须显式告知 |
| T5 | 错误可见 | 扫描失败就地显示 issue banner；部分失败不写「扫描完成」；不静默跳过 |
| T6 | 数据不出本机 | 设置页脚固定「所有数据都留在本机」；界面无账号、无同步、无网络请求 |

### 1.5 UX 成功标准

- 新用户从打开到完成第一次「废纸篓清理」，**不读文档**也能说清「这次没有释放空间」。
- 清理确认框打开后，用户能在一屏内回答三个问题：删哪些 Agent、会去哪、能不能撤销。
- 发生误删时，用户在 60 秒内能找到三个撤销入口中的至少一个。

## 3. 信息架构与心智模型

### 3.1 对象模型

```
本机
├── Agent（内置目录 + 用户适配器）
│   ├── 身份：id / 名称 / 厂商 / 分组（cli · ide · app · extension · other）
│   ├── 状态：已安装 / 未安装 / 读取失败
│   ├── 1 — N 会话
│   └── 存储：会话正文（file · dir · sqlite）+ 索引位置
│
├── 会话（uid = agentId:id，全局唯一）
│   ├── 标题 / 摘要 / 项目路径 / 消息数
│   ├── 体积（SQLite 单行可能无法计算，显示 —）
│   ├── 最后更新 / 是否活动（active）
│   └── 文件位置（0..N 条路径）
│
├── 批次（一次清理的用户可见回执）
│   ├── 时间 / 条数 / 涉及的 Agent / 真实释放 / 是否可撤销
│   └── 内部可能拆成 N 份 journal（按 Agent），UI 始终只展示一个批次
│
├── 发现候选（还没收录的目录）
│   ├── 路径 / 名称 / 置信度 / 证据 / 会话数 / 体积
│   └── 收录后 → 生成一条用户适配器
│
└── 适配器（内置只读；用户适配器可增）
    └── 收录候选 = 写一条适配器 → 下一轮扫描纳入
```

### 3.2 三层收敛

用户对数据的理解只需要三层，界面也按这三层组织：

```
全部会话（所有 Agent 的并集）
   │  点侧栏 / ⌘K 选 Agent
   ▼
一个 Agent 的会话（可再叠加搜索、筛选、排序）
   │  点一行 / ↑↓
   ▼
一条会话的详情（只此一条，焦点驱动）
```

- **列表永远只展示一个视角**：全部会话，或某个 Agent。搜索/筛选是叠加在视角上的条件，不产生新页面。
- **选择可以跨视角存在**：勾选属于集合，不属于当前列表；被筛掉时必须显式提示（§8 R7）。

│ 分组     │ 会话行                                 │ 清理影响         │

├──────────┴───────────────────────────────────────┴──────────────────┤

└─────────────────────────────────────────────────────────────────────┘

浮层（z 20–40）：筛选/快速选择菜单、右键菜单、命令面板、设置抽屉、发现抽屉、清理确认对话框、快捷键表、toast

### 3.4 心智模型：看、选、清是三种不同的事

```
         点击行 / ↑↓ / J K / ⌘K 跳转
                    │
                    ▼
              ┌──────────┐       详情面板跟随
              │  焦点     │ ───────────────────▶  只影响「看什么」
              │ focusUid │
              └────┬─────┘
                   │ 空格 / X / 复选框 / Shift 连选 / ⌘A / 快速选择
                   ▼
              ┌──────────┐       状态栏摘要 + 清理按钮
              │  选择     │ ───────────────────▶  只影响「清理什么」
              │ selected │
              └────┬─────┘
                   │ 清理按钮 / ⌘⌫ → 确认 → 执行
                   ▼
              ┌──────────┐       批次回执 + 撤销
              │  批次     │ ───────────────────▶  只影响「发生了什么」
              └──────────┘
```

三句话记法，也用于空状态与帮助文案：

1. **点击只是看，勾选才是选。**
2. **移入废纸篓不等于释放空间。**
3. **一次清理是一个批次，一个批次可以整体撤销。**

### 3.5 术语（只列出容易混淆的）

| 用 | 含义 | 不用 |
|---|---|---|
| Agent | 一款 AI 工具；会话的归属 | AI 助手、AI 工具（作为侧栏标题） |
| 会话 | 一条可清理的记录，可能对应文件/目录/SQLite 行 | 对话、聊天记录 |
| 清理 | 上位动词，包含两种方式 | 扫除、清扫 |
| 移入废纸篓 | 默认可逆方式；不释放空间 | 删除（当指废纸篓时） |
| 永久删除 | 跳过废纸篓，不可撤销 | 直接删除、彻底删除 |
| 真实释放 | 磁盘上实际减少的字节数 | 释放空间（对废纸篓模式） |
| 索引备份 | 改索引前复制到应用支持目录的副本 | 元数据备份 |
| 批次 | 一次清理产生的可撤销回执 | 任务、作业 |
| 发现 / 收录 | 找到未收录目录 / 写入适配器 | 扫描新 Agent、添加 Agent |
| 适配器 | 描述一个 Agent 数据位置的声明 | 插件、驱动 |

## 4. 核心流程

流程写在「用户视角」：每个动作发生后，屏幕上必须出现什么、焦点落在哪、失败时往哪退。所有破坏性动作都遵循同一条底线：**确认前不写盘，执行中不静默，结束后有回执。**

通用约定：

- 「就绪」指扫描完成、列表有数据、没有浮层、没有进行中的删除。
- 扫描中始终可以浏览、勾选、看详情；删除中不行（§5.1 优先级）。
- 输入框聚焦时，除 `⌘K` / `Esc` 外不触发全局快捷键；浮层打开时背景列表不可交互，关闭后焦点回到触发元素。

### 4.1 首次打开

**触发**：启动应用；或点击顶栏品牌「AgentSweep」回初始视图（清空筛选与搜索，不改变选择）。**前置**：没有已加载数据；「启动时自动扫描」默认为开。

**步骤与系统反馈**

1. 三栏骨架立即就位：侧栏「Agent」+ 占位计数，列表 8 行 skeleton，详情空态，状态栏「正在读取本机会话…」（C-05）；不显示「0 条」。
2. 读取首屏数据；如果自动扫描为开，进入扫描态（§4.2），列表继续显示 skeleton。
3. 数据到达：渲染侧栏、列表、详情；**自动聚焦第一条可见会话，不勾选**；清理按钮保持禁用，tooltip C-58。
4. 扫描完成且 0 条会话：显示空态 C-60；状态栏「扫描完成 · 0 条会话」。
5. 有失败项：列表顶部显示 issue banner C-70，不阻塞浏览。
6. 自动扫描为关：状态栏「尚未扫描」，列表显示未扫描空态 C-59。

**失败与退出**：首屏读取失败显示 C-65 与「重试」，不加载演示数据（R14）；自动扫描失败按 §4.9 处理；关闭窗口不写数据、不保留选择。

**焦点与键盘**：首屏不抢 DOM 焦点，`Tab` 进入列表落在第一条可见行，`⌘F` 聚焦搜索；空详情时不自动打开详情抽屉；骨架阶段 `⌘R` 不重复触发扫描。

### 4.2 扫描

**触发**：点击「扫描」、`⌘R`、启动时自动扫描、失败后的「重新扫描」。**前置**：没有扫描在跑；删除中禁用（tooltip C-59b）。

**步骤与系统反馈**

1. 立即进入扫描态：按钮「扫描中」并禁用；顶栏下方出现 2px 进度条（`--accent`）；状态栏「扫描中 0/30 · 准备中」。
2. 每 250ms 更新：「扫描中 12/30 · Cursor」；进度条推进；侧栏当前 Agent 状态点脉冲；**旧行留在屏幕上，不闪空态**。
3. 列表为空时显示扫描占位 C-64，而不是普通空态。
4. 完成：进度条收至 100% 后消失；按钮恢复「扫描」；状态栏「扫描完成 · 26 条会话」；toast C-90。
5. 结果合并：新会话按当前排序进入；焦点保留；不存在的 UID 被清理；**不自动选中新会话**。
6. 部分失败：列表顶部 banner C-70；状态栏 C-50d。

**失败与退出**：完全失败时状态栏 C-50e、保留旧数据；无数据时进入 C-65；toast C-81 只出现一次，不用 alert。不能取消扫描；关闭窗口即中断，下次启动重扫。

**焦点与键盘**：扫描不改变焦点、滚动位置和详情；扫描中 `⌘R` 无效，`⌘F`、方向键、空格、`⌘K` 仍可用；完成不抢焦点，读屏通过 `role="status"` 播报。

### 4.3 浏览与筛选

**触发**：点击行、`↑↓` / `J K`、点侧栏 Agent、搜索、筛选浮层、排序表头、命令面板跳转。**前置**：就绪或扫描中（可浏览旧数据）。

**步骤与系统反馈**

1. 点击一行：出现焦点态（`--focus-ring` 外环 + 1px `--accent` 内描边），详情 140ms 淡入更新；复选框、已选摘要、清理按钮**都不变**。
2. `↑↓` / `J K`：焦点在可见行间移动并滚入视口，不循环；详情跟随。
3. `Enter`：详情收起时打开，已打开则保持。
4. `⌘F` 聚焦搜索；输入即筛选标题、项目、摘要、ID、Agent 名；命中标题用 `<mark>` 高亮；`Esc` 清空并回到列表。
5. 筛选浮层：存储（全部/文件/目录/SQLite）、时间（全部/今天/7 天内/30 天内/更早）、体积（全部/小于 10 KB/10 KB–1 MB/大于 1 MB）；即时生效；生效条件显示为可移除 chip；「重置筛选」清空。
6. 排序：标题、体积、最后更新；点击切换升降序；默认最后更新降序；`aria-sort` 同步。
7. 列表摘要更新为「N 条 · X MB」；搜索时「匹配 N 条 · X MB」。
8. 无结果：显示 C-61/C-61b，保留 Agent 与筛选条件，提供「清除搜索」或「重置筛选」，不自动跳回全部。
9. 切换 Agent：滚回顶部，焦点落到第一条可见行；**不清空选择**；有隐藏选中时状态栏显示 C-53。

**失败与退出**：筛选/搜索为 0 只显示无结果态，不改数据、不清选择；点击无会话/未安装 Agent 显示 C-62/C-63 并提供「查看全部会话」。

**焦点与键盘**：焦点行是「我正在看哪条」的唯一信号；筛选导致焦点行不可见时移到第一条可见行，详情跟随；`Esc` 关闭顺序见 §6.4（浮层 → 搜索 → 选择 → 移除焦点）。

### 4.4 选择

**触发**：复选框、`Space` / `X`、`Shift + Space` 或 `Shift + 点击复选框`、表头三态全选、`⌘A`、快速选择、右键菜单、详情底部按钮。**前置**：列表有可见行。

**步骤与系统反馈**

1. 单条切换：复选框选中，行底色 `--selection` + 左侧 2px `--accent` 指示条；焦点也移到该行；状态栏 C-51，清理按钮启用并显示「清理 N 条」。
2. `Shift` 连选：以最近一次普通选择的 `anchorUid` 为锚点，替换为当前可见顺序的连续区间；锚点在下一次普通选择时更新。
3. `⌘A`：选中全部**可见**会话，不清除已被筛掉的已选项。
4. 表头全选：三态；点击在「全选可见」与「清空可见」间切换，只作用于可见集合。
5. 快速选择：菜单提供「超过 30 天」「空会话」「最大 10 条」「全部可见」「清除选择」；执行后**替换**当前选择，状态栏即时更新。菜单项可附带匹配数量提示（原型暂未显示，属增强项）。
6. 右键：未选中时先只选该行再打开确认；已选中多行时菜单文案改为「清理选中的 N 条」，按当前选择打开。
7. 取消最后一条：状态栏 C-51（0 条），清理按钮禁用（tooltip C-58），焦点留在原行。

**失败与退出**：列表为空时 `⌘A`、快速选择、全选均无效果且不报错；选择含被筛掉的行时不静默丢弃，摘要第二行常驻 C-53，确认框列出全部已选；`Esc` 在浮层与搜索都关闭后清空选择，焦点保留。

**焦点与键盘**：`Space` / `X` 只切换焦点行；`Shift + Space` 从锚点连选；选择不移动滚动位置（`Shift` 连选把目标行滚入视口），不改变筛选，不打开详情。

### 4.5 清理（废纸篓 / 永久删除）

**触发**：状态栏「清理 N 条」、`⌘⌫`、右键「清理此条」。**前置**：至少选中 1 条；无进行中的删除或扫描写入冲突。

**步骤与系统反馈**

1. 「清理前显示确认」为关时跳过确认直接执行，但仍产生批次与回执；默认必须为开。
2. 打开 560 宽确认框：标题 C-110/C-112；导语 C-111/C-113；涉及的 Agent chips（按条数降序，单个 Agent 显示「Claude Code × 3」）；空间账本；活动警告 C-119；清理方式分段；永久模式额外显示警告与勾选 C-118；底部「取消」与主操作。
3. 账本按当前模式显示：正文体积来自选中会话；索引备份只写状态（已备份 / 不额外备份），不编造未知体积。

```
移入废纸篓
会话正文    180 KB   移入废纸篓 · 不释放
索引备份     已备份   清理前备份到应用支持目录
真实释放      0 B    清空废纸篓后生效
────────────────────────────────────────────
总计 180 KB（正文，不含索引备份） · 真实释放 0 B

永久删除
会话正文    180 KB   永久删除
索引备份     已备份   清理前备份到应用支持目录
真实释放    180 KB   清理完成后生效
────────────────────────────────────────────
总计 180 KB（正文，不含索引备份） · 真实释放 180 KB

索引体积未知时该行显示「—」，不编造数字。
```

4. 切换模式：账本即时更新；永久模式出现危险警告与勾选，未勾选时确认禁用并保留解释；切换会同步为默认清理方式（小字 C-120b）。
5. 确认：对话框关闭；按钮「正在清理…」并禁用；选中行保持可见并进入待清理态（降低不透明度、复选框禁用），列表不提前删除；禁止重复提交。
6. 成功：移除行、清空选择；焦点移到原位置的下一条可见会话（没有则上一条，列表空则清空）；批次回执 C-54/C-55；toast C-91/C-92。
7. 部分失败：成功行移除，失败行保留选中并标为失败态；toast C-74 带「查看」；回执只统计实际数量。
8. 全部失败：确认框保持原位并显示 C-73；焦点回确认按钮；数据不变。

**失败与退出**：取消、`Esc`、点遮罩关闭且不改数据，焦点回清理按钮，模式偏好保留；删除中不可取消，按钮禁用，只等结果；后端错误显示行内 C-73/C-73b；`batchId` 缺失时仍显示「已移入废纸篓」但不提供撤销（C-54b）。

**焦点与键盘**：打开时键盘焦点落「取消」（安全默认），指针用户焦点在对话框容器；焦点陷阱内 `Tab`/`Shift+Tab` 循环，`Enter` 触发当前按钮，`Space` 切换勾选，`Esc` 取消（删除中除外）；关闭后焦点回触发元素。

### 4.6 撤销

**触发**：toast「撤销」、状态栏批次回执、设置 → 最近清理、`⌘Z`（输入框外、无浮层）。**前置**：存在可撤销批次（移入废纸篓、24 小时内、未撤销）；永久删除不可撤销。

**步骤与系统反馈**

1. 点击任一处撤销：对应按钮「撤销中…」并禁用，其他两处同步忙碌，避免重复。
2. 恢复完成：批次回执变 C-56「已撤销」并移除操作；设置中该行变不可撤销；toast C-93。
3. 恢复的会话被当前筛选隐藏时**不改变筛选**；toast detail 说明「其中 2 条在当前筛选之外」，toast 提供「查看全部会话」。
4. 恢复的会话在可见范围时，焦点落到第一条恢复的会话；选择保持空，不自动选中。

**失败与退出**：超过 24 小时、已撤销、文件被移动时 toast C-75 并变不可撤销；部分失败用 C-75b，不谎报全部成功；撤销无二次确认，也没有 redo（§9.2）。

**焦点与键盘**：`⌘Z` 只撤销最近一个可撤销批次，焦点不离开当前行；输入框内 `⌘Z` 仍是系统文本撤销；撤销中禁用重复 `⌘Z`，完成后再按不会撤销更早的批次（§9.3 C-3）。

### 4.7 发现与收录

**触发**：顶栏「发现」（带未收录数量）、`⌘⇧D`。**前置**：无；发现是只读探测，不修改文件。

**步骤与系统反馈**

1. 打开 640 宽抽屉：标题「发现」、副标题 C-10b；列表先显示 3 张 skeleton 卡片。
2. 约 600ms 后渲染候选：名称、路径、置信度（细进度条 + 百分比）、证据 chips（最多 3 条）、会话数/体积、建议分组、主按钮「收录为 Agent」。
3. 按置信度降序；0 个候选显示 C-66；读取失败显示错误态 +「重新检查」。
4. 点击收录：按钮「正在收录…」；成功后卡片移除或变「已收录」，侧栏新增 Agent（建议分组或「其他」），toast C-95。
5. **不自动切换筛选、不自动选中新 Agent**；新 Agent 行短暂高亮 1.6 秒并滚入视口，由用户决定是否点它。
6. 「重新发现」：重新探测；无新候选 toast C-96，有则更新列表与顶栏计数。

**失败与退出**：读取失败保留已有候选并在抽屉内显示错误态 + 重试；收录失败恢复按钮并 toast C-76，不关闭抽屉；`Esc`/遮罩/关闭按钮关闭，焦点回「发现」按钮。

**焦点与键盘**：抽屉焦点陷阱；`Tab` 在候选卡片间移动；`Enter` 触发当前聚焦的「收录为 Agent」；收录成功后焦点留在原卡片位置或下一张，不跳到侧栏。

### 4.8 设置

**触发**：齿轮按钮、`⌘,`。**前置**：无；所有设置即时生效，没有「保存」。

**步骤与系统反馈**

1. 打开 420 宽抽屉：标题「设置」、副标题「更改会立即保存」。
2. **清理方式**：分段「移入废纸篓」（默认）/「永久删除」；hint 随选择变为 C-131/C-132；切换后状态栏清理按钮样式与账本同步。
3. **行为**：清理前显示确认、包含快照、启动时自动扫描（默认均为开）；即时写入，失败回滚并 toast C-77。
4. **外观**：自动/浅色/深色；立即应用，`auto` 跟随系统。
5. **最近清理**：按时间倒序列出；每行时间、条数、方式、真实释放；可撤销批次显示「撤销」；空态 C-67；最多展示最近 5 条。
6. **索引备份**：说明路径 `~/Library/Application Support/AgentSweep/backups/`，提供「打开备份目录」（原型 toast，生产打开 Finder）。
7. 关闭：`Esc`/遮罩/关闭按钮；焦点回齿轮；焦点陷阱有效。

**失败与退出**：偏好写入失败回滚原值并 toast C-77，抽屉不关闭；撤销失败行显示 C-57b「恢复失败」并 toast C-75，其他行不受影响。

**焦点与键盘**：`↑↓` 在分组间移动焦点，`Tab` 进入控件，`Space` 切换开关，分段用 `←→`；关闭后滚动位置回顶部，设置值保留。

### 4.9 扫描失败

**触发**：扫描返回 `status=error`，或完成但 `issues` 非空。**前置**：用户刚发起或自动执行了一次扫描。

**步骤与系统反馈**

1. 部分失败：列表顶部插入 banner（`--warn-bg` 底、`--warn` 文字）：图标 + C-70 +「查看详情」+「重试」。
2. 展开：逐条显示「Agent 名称 · 错误原因 · 路径」，每条带「重试」；原因用用户能懂的话（权限、文件被占用、格式无法解析）。
3. 完全失败：状态栏 C-50e；无数据时显示 C-65（不是普通空态）；有旧数据时保留旧列表并加 banner C-72。
4. 重试：只重试失败来源，不清空成功项；重试中 banner 显示「正在重试…」并禁用按钮。
5. 重试成功：banner 消失，状态栏更新；不弹 toast，避免噪声。
6. banner 可收起为状态栏「N 个来源读取失败」；下次扫描重新计算，不继承旧错误。

**失败与退出**：重试仍失败时保留 banner，不重复弹 toast，文案说明「仍然无法读取」与下一步；用户可忽略 banner 继续浏览与清理；无数据时 C-65 只提供「重新扫描」，不提供清理。

**焦点与键盘**：banner 不移动焦点、不打断滚动；`Tab` 可到「查看详情」与「重试」；展开后焦点进入问题列表，`Esc` 收起；读屏用 `role="status"` 播报失败数量。

## 5. 状态清单与状态矩阵

### 5.1 状态定义与优先级

| 状态 | 含义 | 进入条件 | 退出条件 |
|---|---|---|---|
| 首次加载 | 首屏数据未到 | 启动 | 数据到达 / 失败 |
| 空 | 确实没有会话，或尚未扫描 | 扫描完成且 0 条；或 autoScan 关闭 | 扫描出结果 / 用户点扫描 |
| 无结果 | 有会话，但当前搜索/筛选为 0 | 搜索或筛选命中 0 | 清除搜索/重置筛选/换 Agent |
| 扫描中 | 扫描任务运行 | 点击扫描 / `⌘R` / 自动扫描 | 完成 / 失败 |
| 部分失败 | 扫描完成但有 issues | `issues.length > 0` | 重试成功 / 下次扫描 |
| 删除中 | 清理请求已提交 | 确认清理 | 成功 / 失败 |
| 已撤销 | 某个批次被撤销（批次状态，不是全屏状态） | 撤销成功 | 无（只影响该批次） |

同时存在多个状态时的优先级（从高到低）：**删除中 > 扫描中 > 部分失败 > 就绪 > 空/加载**。删除中，清理入口与选择操作禁用；扫描中，清理仍可用但结果刷新延后到清理结束。

### 5.2 屏幕 × 状态矩阵

| 区域 | 首次加载 | 空 | 无结果 | 扫描中 | 部分失败 | 删除中 | 已撤销 |
|---|---|---|---|---|---|---|---|
| 顶栏 | 搜索/发现可用；扫描禁用 | 扫描可用 | 扫描可用；`⌘F` 清除搜索 | 扫描按钮「扫描中」禁用；进度条显示 | 扫描可用；可加问题计数 | 扫描/发现/设置禁用或降级 | 同就绪 |
| 侧栏 | 计数占位「—」 | 全部会话 0 条；Agent 可点开看空态 | 保持不变 | 当前读取 Agent 状态点脉冲；旧计数保留 | 失败 Agent 加「读取失败」标记 | 计数保持，删除行不提前消失 | 计数恢复，新增被恢复的会话归属 |
| 列表头 | 标题「全部会话」，摘要「正在读取…」 | 摘要「0 条」；无筛选 chip | 摘要「匹配 0 条」；筛选 chip 可见 | 摘要保留旧值或「正在扫描…」 | 列表头上方插入 banner C-70 | 摘要保留清理前值 | 摘要更新为恢复后的数量 |

### 5.3 状态转换

```
启动 ─▶ 首次加载 ─┬─ 成功 ─▶ 就绪 ─┬─ ⌘R / 扫描 ─▶ 扫描中 ─┬─ 完成 ─▶ 就绪 / 空
                  │                 │                        └─ 失败 ─▶ 部分/完全失败 ─ 重试 ─▶ 扫描中
                  └─ 失败 ─▶ 错误空态 ─ 重试 ─▶ 扫描中

就绪 ─ 勾选 ─▶ 有选择 ─ 清理 / ⌘⌫ ─▶ 确认框 ─┬─ 取消 ─▶ 就绪（焦点回清理按钮）
                                               └─ 确认 ─▶ 删除中 ─┬─ 成功 ─▶ 批次回执 ─ 撤销 ─▶ 已撤销
                                                                  └─ 失败 ─▶ 确认框错误
```

### 5.4 状态守恒规则

1. **焦点守恒**：焦点行被删除或过滤掉时，移动到原位置的下一条可见行；没有下一条则上一条；列表为空则清空焦点并显示空详情。
2. **选择守恒**：筛选、搜索、排序、扫描都不得改变选择；只有用户选择动作、清理成功、撤销成功可以改变。
3. **滚动守恒**：扫描完成、详情更新、勾选都不重置列表滚动；切换 Agent/筛选与排序重置到顶部。
4. **不闪空**：任何有旧数据的刷新都保留旧行，直到新数据到达；禁止先清空再渲染。
5. **不抢焦点**：toast、banner、扫描完成、新批次都不移动 DOM 焦点。
6. **失败不成功**：部分失败的状态栏与回执必须包含失败数量；不得只用成功文案。

### 6.4 焦点与 Esc 顺序

- 焦点环：2px `--focus-ring`，offset 2px；行焦点环叠加 1px `--accent` 内描边。焦点不靠颜色单独表达，读屏用 `aria-selected` 与行序号。
- 进入列表：`Tab` 从搜索进入表格的第一个焦点行；`Shift+Tab` 反向离开。
- `Esc` 严格按以下顺序消费，一次只做一件事：

```
1. 有清理确认框 → 关闭（删除中不关闭）
2. 有设置/发现/命令面板/快捷键表 → 关闭
3. 有筛选/快速选择/右键菜单 → 关闭
4. 搜索框有内容 → 清空搜索并保持聚焦
5. 有选择 → 清空选择
6. 焦点在搜索框 → 失焦回到列表
7. 有焦点行 → 移除焦点（详情回到空态）
```

- 浮层关闭后焦点回到打开它的元素；该元素不存在时回到搜索框；删除中除 `Esc`（无效但被消费）外全部快捷键禁用。

## 7. 文案库

### 7.1 写作原则

1. **先说结果，再说解释。** 标题说发生了什么，第二行才补充原因或下一步。
2. **数字必须可核对。** 体积、条数、时间都来自当前数据；估算只在 SQLite 单条体积等确实无法得知时使用「约」，其余不写「约」。
3. **不用感叹号、不用「Oops」「哎呀」、不用 AI 套话。** 错误直接说原因与下一步。
4. **一句动作用一个动词。** 「清理」「移入废纸篓」「永久删除」「撤销」互不替代。
5. **英文术语只在必要处保留。** Agent、SQLite、Finder、Application Support 保持原样；其余说中文。
6. **长度上限**：按钮 ≤ 8 个汉字；标题 ≤ 24 字；正文单句 ≤ 60 字；toast 主文案 ≤ 20 字，detail ≤ 40 字。

### 7.12 数字、时间与单位

- 字节用 1024 进制：`0 B`、`180 KB`、`1.5 MB`、`3.3 MB`；不写 `0KB`、`1,024 KB`。
- 条数统一「N 条」，不写「个」；体积数字右对齐、等宽（`stat` 字阶）。
- 时间：列表用「今天 19:32 / 昨天 / 周四 / 9月12日」，详情用「2026年10月17日 19:32」；扫描用时写「2.4 秒」。
- 百分比只用于发现置信度（82%）；不写「约」除非确实无法精确得知。

## 8. 安全与边界规则

这些规则是产品承诺的硬边界。实现可以不同，用户可见行为必须一致。

| # | 规则 | 用户可见行为 |
|---|---|---|
| R1 | **只读扫描** | 扫描期间不写任何文件；扫描按钮完成前后都是「扫描」；没有「已修改 N 个文件」的提示 |
| R2 | **浏览 ≠ 选择** | 点击/↑↓/J K 只更新详情；只有复选框、空格、X、⌘A、快速选择、右键、详情按钮改变选择 |
| R3 | **默认可逆** | 默认「移入废纸篓」；清理方式会被记住，但即使默认为永久删除，每次确认仍需勾选 C-118 |
| R4 | **活动会话用黄色警告** | 徽标与 callout 用 `--warn` / `--warn-bg`；确认框显示 C-119；不阻止清理，但明确建议先退出对应 Agent |
| R5 | **永久删除才用危险红** | `--danger` / `--danger-bg` 只用于永久删除相关控件；废纸篓清理按钮保持墨色；永久模式确认按钮在未勾选 C-118 时禁用 |
| R6 | **跨 Agent 批次** | 一次确认可以包含多个 Agent；确认框按 Agent 分组显示条数；内部多份 journal 对用户只呈现一个批次回执；撤销作用于整批 |
| R7 | **隐藏选中不丢失** | 筛选/搜索不改变选择；状态栏常驻 C-53；确认框列出全部已选（含当前视图外）；用户可在确认前取消 |
| R8 | **刚扫描不覆盖用户上下文** | 扫描完成不自动选中、不抢焦点、不重置滚动；焦点会话被删除时移到下一条；选择中的 UID 全部重校验 |
| R9 | **撤销窗口 24 小时** | 只有废纸篓批次可撤销；超过 24 小时显示「不可撤销」；永久删除永不可撤销；撤销无二次确认 |
| R10 | **索引先备份** | 任何索引/SQLite 修改前先备份到 `~/Library/Application Support/AgentSweep/backups/`；备份不删除、不自动清理；备份体积不计入真实释放 |
| R11 | **SQLite 不编造单条体积** | 列表显示 `—` 或 0；详情说明「正文在数据库中」（C-127）；真实释放按 VACUUM 前后差值；撤销还原整库 |
| R12 | **删除中不可并发** | 清理中禁用清理按钮、扫描、右键清理；确认框不可取消；关闭窗口视为中断，下次以批次回执为准 |
| R13 | **部分失败不谎报** | 回执与 toast 必须包含失败数量；失败行保留；不写「全部完成」；错误给原因与下一步 |
| R14 | **演示数据不进生产** | 生产构建不静默降级到演示数据；原型通过控制台显示演示条。演示会话不能触发真实清理 |
| R15 | **本地与隐私** | 无网络请求、无账号、无遥测；设置页脚 C-142；路径只在用户点击时打开 Finder |
| R16 | **权限与锁** | 权限错误用 C-78，数据库锁用 C-79；不静默跳过失败来源；不要求用户手动删文件 |
| R17 | **不读会话正文** | 扫描只提取元数据与摘要；详情不播放/展开完整对话；不提供导出正文 |
| R18 | **不代用户做危险决定** | 不自动清理、不默认永久删除、不默认全选、不在后台删除；每次破坏性操作都来自用户确认 |

补充说明：

- **活动会话**：`active=true` 只表示「文件最近被修改」，不是进程锁。因此用「可能正在使用」，不用「正在使用」；不因 active 阻止清理。
- **跨 Agent 批次**：如果后端返回多个 `batchIds`，前端仍只展示一个回执；撤销时按顺序撤销全部并合并结果。用户不需要理解 journal。
- **撤销窗口之外**：批次仍保留在最近清理列表中，但按钮变为「不可撤销」；不提供「联系支持」等无效出口。
- **备份保留**：v1 不提供清理备份的 UI；在设置中说明备份位置与「不会自动删除」，避免用户以为清理已彻底释放。

## 9. 设计决策、未做范围与待定问题

### 9.1 关键决策与取舍

| # | 决策 | 放弃的方案 | 理由 | 代价与缓解 |
|---|---|---|---|---|
| D1 | 浏览与选择分离 | 点击行即选中（当前实现） | 降低误清空；详情可以自由看 | 多一步勾选；用 40px 复选框、空格、快速选择缓解 |
| D2 | 默认移入废纸篓 | 默认永久删除 | 可逆优先；新用户安全 | 磁盘不立即释放；用账本与「真实释放 0 B」明说 |
| D3 | 一次清理只确认一个批次 | 每条弹出确认 / 流式删除 | 批量效率与回执清晰 | 批次可能很大；用 Agent 分组与条数预览 |
| D4 | 确认框使用空间账本 | 一句「删除 3 条会话？」 | 把「去哪 / 释放多少 / 能否撤销」一次说清 | 阅读成本；三行、等宽数字、短句控制 |
| D5 | 撤销三入口 + `⌘Z` | 只靠 toast | toast 会消失；三处覆盖发现路径 | 状态栏空间；chip 保持单行紧凑 |
| D6 | 扫描不打断浏览 | 全屏 loading / 清空列表 | 用户可以在扫描中继续处理旧数据 | 列表可能是旧的；状态栏与完成 toast 标明时间 |
| D7 | 问题就地 banner | 弹窗 / 只写日志 | 不打断浏览，又能看见失败来源 | banner 易被忽略；状态栏保留警告链接 |
| D8 | 活动会话黄色警告 | 红色阻止 / 静默允许 | 不制造恐慌，也不隐瞒风险 | 用户仍可能删掉活动会话；确认框再次提醒 |
| D9 | 永久删除勾选确认 | 双击确认 / 输入文字 | 勾选是 macOS 常见且可访问的模式 | 仍可能误勾；危险色 + 账本 + 不可撤销说明 |
| D10 | 筛选不改变选择 | 筛选时清空选择 | 避免用户以为选择被丢弃 | 可能清理到看不见的会话；C-53 与确认框强制披露 |
| D11 | 账本不编造索引体积 | 用演示数字填充 | 诚实优先；索引体积未在扫描数据中 | 已知时显示实际备份体积，未知时显示「—」与去向；清理回执可补实际备份大小 |
| D12 | 收录后不自动跳转 | 自动切到新 Agent | 不替用户改变上下文 | 用户要多点一次；用短暂高亮与 toast 指路 |

## 10. 验收清单

### 10.1 信任与数字

- [ ] 首次打开自动聚焦第一条，未勾选，清理按钮禁用且 tooltip 为 C-58。
- [ ] 点击、`↑↓`、`J K` 只改焦点与详情，不改选择、不启用清理。
- [ ] 废纸篓确认框有三行账本，真实释放 `0 B` 且含「不释放」。
- [ ] 永久删除确认框首行/总计为危险色，真实释放等于选中体积（SQLite 按 VACUUM 说明）。
- [ ] 废纸篓成功文案不说「释放」；永久成功使用「真实释放」。
- [ ] 状态栏已选摘要第二行常驻「真实释放」；账本未知索引体积显示「—」。

### 10.2 核心流程

- [ ] 首次打开：骨架 → 数据 → 聚焦第一条；无「0 条」闪烁、无演示数据。
- [ ] 扫描：按钮「扫描中」、顶栏进度、状态栏 `12/30 · Cursor` 同步，完成 toast C-90。
- [ ] 扫描中可继续浏览/勾选/看详情，旧行不消失。
- [ ] 搜索、三类筛选、排序可组合；chip 可移除；无结果有出口。
- [ ] 复选框、空格、X、Shift 连选、⌘A、三态全选、快速选择、右键、详情按钮结果一致。
- [ ] 清理全流程：确认 → 行 pending → 移除 → 批次回执 → toast；部分失败行保留并带「查看」。
- [ ] 撤销三入口与 `⌘Z` 均可撤销同一批次；发现收录后不自动切换筛选；设置项即时生效。

### 10.3 状态与失败

- [ ] 加载、空、无结果、扫描中、部分失败、删除中、已撤销的表现与 §5.2 一致。
- [ ] 部分失败 banner 可展开逐 Agent 问题并重试；状态栏同步失败数。
- [ ] 完整失败且无数据时显示 C-65，不是普通空态；重试只重试失败来源。
- [ ] 扫描完成不自动选中、不抢焦点、不重置滚动。
- [ ] 焦点行被删除/过滤时按 §5.4 移动；筛选/搜索/排序不改变选择。
- [ ] 隐藏选中显示 C-53，确认框包含当前视图外的已选项。

### 10.4 键盘与无障碍

- [ ] §6 全部快捷键按表生效，不与输入框冲突；`Esc` 严格按 §6.4 顺序消费。
- [ ] 行可 Tab 到达，焦点行 `tabindex="0"`，焦点环可见；`aria-selected`/`role="grid"`/`role="status"` 正确。
- [ ] 对话框/抽屉/面板焦点陷阱有效，关闭后焦点回触发元素。
- [ ] `prefers-reduced-motion` 下无动画；对比度满足 DESIGN §9。
- [ ] 纯键盘可完成「扫描 → 筛选 → 选择 → 清理 → 撤销」全流程。

### 10.5 文案与安全

- [ ] 无感叹号、无「Oops」、无 AI 套话；术语统一（Agent/会话/清理/移入废纸篓/永久删除/真实释放/撤销/批次/发现/收录/适配器）。
- [ ] 活动会话统一「可能正在使用」；空状态有下一步；错误有原因+下一步。
- [ ] 数字、时间、单位符合 §7.12；toast 主文案 ≤ 20 字、detail ≤ 40 字、操作 ≤ 1 个。
- [ ] 扫描只读；永久删除必须勾选 C-118；删除中不可取消、不可重复提交、不可并发扫描。
- [ ] 跨 Agent 只出现一个批次回执；索引备份路径与「不自动删除」可见；SQLite 不编造单条体积。
- [ ] 生产构建不加载演示数据；原型演示条与产品 UI 明显区分。

### 10.6 与 DESIGN / CONTRACT 一致性

- [ ] 三栏尺寸与断点符合 DESIGN §5（232/332/56/44；1120/1000）；警告/危险/成功/焦点只用对应 token。
- [ ] CONTRACT 4.2–4.7 的 ID 与行为钩子完整；5.10 快捷键无遗漏；toast 最多 3 条、6 秒、悬停暂停。
- [ ] 1180×760、1440×900、960×700 三档不溢出、不横向滚动，详情/侧栏按断点收起。
